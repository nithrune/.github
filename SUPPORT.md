# Support

## Before opening anything

Read the repository's own `README.md`, and its `INSTALL.md` if it has
one. Most reports turn out to be something already documented there —
a setting that has to be changed before anything works, a command used
without a required argument, or a behaviour that only functions under
the conditions the docs spell out.

## Where to go

| You want to | Do this |
|---|---|
| Report a bug | Open an issue on the repository it affects |
| Report a security problem | **Not** an issue — see [SECURITY.md](SECURITY.md) |
| Suggest content or a feature | Open an issue and say what problem it solves |
| Ask how something works | Open an issue; if the answer is not in the docs, that is a docs bug |
| Ask about third-party software | Ask whoever maintains it — not here |

## What makes a report usable

- English. It is the only language everyone here reads.
- Which repository, and which version or commit of it — `v1.2.0`, or
  `4e250ab`. Not "latest".
- The server or client software, with version **and build** where it has
  one — `Paper 26.2 (build 119)`. Not "newest".
- Everything else installed that could be involved, each with its version
  — `AutoRank v23.1`. Or "none", which is also an answer.
- The **exact** console output. Not a paraphrase, not a screenshot of a
  screenshot — the text, in a code block.
- What you expected to happen instead.

"latest", "newest" and "current" are not versions. They mean something
different next week, and they make a report impossible to reproduce.

A stack trace with the surrounding twenty lines of log is worth more than
several paragraphs describing it.

## What this is not

Spare-time work, offered as-is. There is no service level, no guaranteed
reply, and no support for modified copies. Nobody here can help with the
rest of your setup.
